# LongMemEval（公开基准）

[LongMemEval](https://github.com/xiaowu0162/LongMemEval)（Wu 等，ICLR 2025，MIT）：500 道题，每题带自己的一段历史（约 50 次会话、500 轮对话），问的是说过一次的事、跨会话的事、后来**改过**的事、和时间有关的事。数据不进仓库：`tests/eval/longmemeval.sh fetch` 下载并校验，`make test-longmemeval` 运行（`tests/eval/README.md`）。

这里量的是**检索**（CMI 的部分；答题是阅读模型的事）：每道题的历史存进它自己的主体作用域，一轮对话一条情景记忆，文本就是 idp-host 写的那种（用户一句加助手一句，各截到 1500 字），在提问的日期用题目文本取前 10 条。

指标（会话级，和论文一致；30 道“无可回答”的题不计）：前 k 条所属的会话里**有任一**证据会话（any）、**全部**证据会话都在（all）；前 10 条里有没有**含答案的那一轮**；对“知识更新”题，**最新**那次证据会话在不在前 k 条里（当前值在那一次里，取不回来谁也答不对）。证据之间谁排在前面不量：只要每条带着日期，顺序不影响答题（见文末的阅读模型实验）。

## 顺序重要吗：阅读模型实验

包里的条目按相关度排。问一件后来改过的事时，旧的那次常常排在新的那次前面，要不要把新的挪到前面？实验（`tests/eval/longmemeval_reader.py`）：同一个包，只改两件事再让模型答题——条目的**顺序**（CMI 给的相关度顺序、按时间新的在前、按时间旧的在前）和条目**带不带日期**（带日期时每条前面是 idp-host 交给模型的那一行，`CMI memory from idp-host (informational, observed <时间>)`；不带时去掉 `observed <时间>`）。裁判是同一个模型，按 LongMemEval 给裁判的要求对照标准答案判对错。

阅读模型 `qwen3.8-flash-next-iq3_xxs`，裁判 `qwen3.8-flash-next-iq3_xxs`；配置 `hybrid-qwen3-0.6b-instruct-f0.20-b0.05`，72 道 knowledge-update 题，每题 10 条。每格：答对 / 答错 / 答“不知道” / 没答出来。

| 顺序 | 带日期 | 不带日期 |
|---|---|---|
| 相关度（CMI 的顺序） | **63** / 6 / 3 / 0 | **50** / 18 / 3 / 1 |
| 按时间，新的在前 | **63** / 6 / 3 / 0 | **46** / 24 / 2 / 0 |
| 按时间，旧的在前 | **63** / 8 / 1 / 0 | **63** / 8 / 1 / 0 |

读法：带日期的三行如果只差几题，说明模型是看日期判断哪个是当前值的，顺序不起作用；不带日期的三行差得多，说明没有日期时模型按“越靠后越新”来猜。由此定下的做法见 ADR-0001 D43：包内顺序不按时间调整，消费方必须把每条的 `observedAt` 交给阅读模型。
